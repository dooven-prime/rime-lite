# Exploratory Experiments

**Research status:** public routing index for Research Program packages and
pre-admission controls.

**Execution status:** documentation-only; each child package declares its own
runnable commands or explicit non-runnable boundary.

**Paper evidence:** none by directory placement. Paper evidence remains owned
by paper-local experiment maps and source-addressed release records; a paper
may explicitly register a bounded subset of a public exploratory package.

This directory contains research-program packages and pre-admission controls.
Most packages are not evidence for a released paper and none is an entry in
the public SOF Registry by directory placement alone. A package may support a
paper, including Paper XIII, only when a specific result is source-addressed
and explicitly registered by that paper's experiment README and release
manifest. Each package must declare its object, carrier, evidence boundary,
validation commands, and promotion conditions.

The exploratory line is parallel to the paper line. Papers VIII-XIII define
the typed objects, admissibility, evidence, reports, and comparison interfaces
consumed here. These packages test candidate quantities, comparison controls,
and new carriers without changing those contracts or importing downstream
action semantics.

## Public Package Contract

Public visibility does not give an exploratory result paper-evidence,
certificate, theorem, Registry, or release status. Every package published
under this directory must provide, in its nearest `README.md`:

- a `Research status` declaration using the repository claim vocabulary;
- an `Execution status` with runnable commands, or a specific reason the
  package is not currently runnable;
- a `Paper evidence` declaration stating that promotion requires an explicit,
  source-addressed paper-local registration;
- a `Known Nonclaims` section naming the strongest nearby conclusions that
  the package does not establish.

Public exploratory packages must contain no credentials, API keys, private
datasets, personal machine paths, or undeclared external data dependencies.
Generated results must identify their finite scope and validator. A script
that runs successfully remains an exploratory control unless an owning paper
separately registers its exact source, output digest, claim, and evidence
status.

A documentation-only route or archived package may be non-runnable by design,
but its README must say so. An environment-dependent formal layer must name
the missing toolchain or dependency instead of presenting uncompiled source as
a checked proof.

## Promotion Rule

An exploratory result may be proposed for promotion only after all of the
following are recorded:

1. the carrier, sectorization origin, observable family, and construction are
   explicit;
2. the parameterization, alignment or fixed-frame context, norm, threshold,
   cutoff, and sampling policy are explicit;
3. a reproducible run and a source-addressed result are available;
4. an independent validator, controlled comparison, or counterexample search
   checks the result;
5. the owning paper or contract is identified, together with the exact claim
   that would change.

Until a versioned reopening is accepted, the result remains a local
`Computational Observation` or `Research Program` item. Exploration must not
modify the object language of a published paper, fill a missing carrier by
analogy, or turn a bounded pattern into a theorem. Runtime adapters and large
application executions belong in `sof-runtime` once their upstream contracts
are frozen.

## Known Nonclaims

Directory placement does not make any package a paper dependency, public
Registry entry, accepted theorem, Computational Certificate, natural cover
theory, sheaf construction, cross-fiber transport law, or action/policy
system. Those statuses require their own owning contracts and promotion
records.
