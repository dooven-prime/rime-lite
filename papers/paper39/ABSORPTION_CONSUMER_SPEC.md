# Event-Anchored Absorption Consumer

## Independent specification from execution logs

**Scope:** the named consumer of the Paper XXXIX draft, specified independently
from its state representations. This specification uses raw executions and occurrence-indexed logs.
It does not use trees, model markers, or the forest's read table. Its realization
is proved in [Paper XXXIX Theorem 4.1](Paper%20XXXIX.md), with
[supplementary proof details](ABSORPTION_CONSUMER_ADEQUACY.md).

## 1. Task and source domain

The task is to select one actual fusion event and monitor its causal
continuation: where its atoms are now, which subsequent fusions absorbed their
carrier, and which partner and event addresses each absorption used. Unrelated
fusions may occur between those absorptions. Selecting an event does not mean
continually selecting the latest event.

Fix $Q=\mathbb Z/n\mathbb Z$, $n\ge2$, the labelled cycle $p(q)=q+1$, and a
rank-$(n-1)$ defect $d$ with binary kernel $K=\{k_0,k_1\}$ and collision image
$c$. Fix a finite atom set $\Omega$ with $2\le N=|\Omega|\le n$ and an
injective seed placement $\iota:\Omega\hookrightarrow Q$. The initial raw
partition places singleton $\{x\}$ at $\iota(x)$.

A history $h$ is any finite chronological word in $p,d$, replayed on this
partition by raw packet push-forward. There is no word-length budget, shortest
filter, checkpoint rule, or success predicate. Write $P_h$ for its final
placed partition and $T_h$ for its support.

At fixed $N$, each fusion reduces the root count by one, so there are at most
$N-1$ fusion events in a history. Unbounded execution length allows arbitrarily
many plateau steps; it does not mean arbitrarily many fusions at that fixed
atom count.

## 2. Event log and registration

When both kernel positions are occupied at a $d$ occurrence, the log records
that occurrence $e$ and its local snapshot

$$
 \operatorname{snap}(e)=(d,b_e,c),\qquad
 b_e:K\longrightarrow\mathcal P_{\ne\varnothing}(\Omega).
$$

Here $b_e(k_i)$ is the packet at $k_i$ immediately before that occurrence.
The fresh block is $F_e=b_e(k_0)\cup b_e(k_1)$. The log has chronological
occurrence identities; the snapshot does **not** return their numeric indices.
Other generator steps do not create log events.

For a supplied nonempty block $F\subseteq\Omega$, registration is defined by

$$
 \operatorname{Reg}(h,F)
 \iff \exists e\text{ in the log of }h:\ F_e=F.
 \tag{Reg}
$$

An occurrence with a given fresh block is unique. Indeed, when $F$ is created,
all its atoms first become one packet. They never split thereafter. A later
fusion involving that packet adds a disjoint nonempty partner, and a fusion
not involving it cannot produce $F$. Thus registration identifies one event
$e_F$, not merely a current packet containing $F$. Registration persists under
every subsequent raw step.

The selected block $F$ is an invocation argument and remains fixed throughout
a continuation. This consumer does not request a numeric timestamp, elapsed
length, or the total ordering of independent events.

## 3. Required state and report

For a registered $(h,F)$, let $(q_h,C_h)$ be the unique current packet and
position with $F\subseteq C_h=P_h(q_h)$. Define the absorption log to be the
chronological subsequence of events **after** $e_F$ at which one pre-event
parent contains $F$. For each such event record

$$
 \operatorname{abs}(e;F)
  =(d,q_e,C_e,s_e,B_e,c,C_e\cup B_e),
 \tag{Abs}
$$

where $C_e=b_e(q_e)$ contains $F$, $B_e=b_e(s_e)$ is its disjoint partner,
and $\{q_e,s_e\}=K$. The containing parent is unique. These are event-time
addresses, not its carrier's later position.

Write $\mathcal A_F(h)$ for the ordered list of these records. The complete
consumer state is the history-derived summary

$$
 U(h,F)=\bigl(P_h,F,\operatorname{snap}(e_F),\mathcal A_F(h)\bigr).
 \tag{U}
$$

Only summaries actually generated by registered histories are in the consumer
state domain. Arbitrary tuples with these field names are not admitted.

The report returns the origin snapshot, the **whole** absorption list, and the
current carrier $(q_h,C_h)$. It is undefined when registration is undefined.
Every field of the two snapshot formats is part of the requested report.

The full current partition $P_h$ is also required in $U$, even though it is not
the whole report: it determines whether another packet collides with the
carrier on the next step. Carrier-local output alone is not presumed to
determine continuation guards.

## 4. Commands, domains, and updates

For $a\in\{p,d\}$ write $f_a$ for its raw transformation. At a registered
state with carrier $(q,C)$ define its next-step collision group by

$$
 G_a(P,q)=\{s\in T(P):f_a(s)=f_a(q)\}.
$$

This group contains $q$ and has size one or two. The consumer offers two
partial commands:

$$
 \begin{aligned}
 \operatorname{Enabled}_{\rm Carry}(U,a)
   &\iff G_a(P,q)=\{q\},\\
 \operatorname{Enabled}_{\rm Absorb}(U,a)
   &\iff G_a(P,q)=\{q,s\}\quad\text{for some }s\ne q.
 \end{aligned}
 \tag{Dom}
$$

Both require registration; outside that domain neither is enabled. On a
registered state they partition the labelled steps. An absorption necessarily
uses $a=d$, with $\{q,s\}=K$ and common destination $c$.

Both commands execute the requested raw step and keep the selected $F$ and its
origin snapshot fixed. They update the full partition to $f_{a\#}P$.

- `Carry(a)` keeps the absorption list unchanged and gives carrier
  $(f_a(q),C)$. It permits a fusion elsewhere in the partition.
- `Absorb(a)` appends $(d,q,C,s,P(s),c,C\cup P(s))$ and gives carrier
  $(c,C\cup P(s))$.

These are the complete update rules. No default state values or additional
admissibility predicates are used. They agree with extension of the independent
execution log: a fusion contributes a record exactly when it involves the
selected carrier. Consequently histories with equal $U$ have equal command
domains and equal next $U$. The commands therefore define deterministic partial
actions on the declared summary domain, not just actions on separate histories.

The same selected event must serve registration, every guard, every report,
and every appended record. Separate event choices cannot be substituted between
commands.

## 5. Complete adequacy obligation

An implementation must establish all of the following on the declared domain:

1. Registration is defined exactly for the logged events specified by (Reg).
2. The origin, entire absorption sequence, and current carrier are correct,
   including every atom block, label, and event-time address.
3. Both command domains agree in both directions, including independent
   fusions during `Carry`.
4. Every legal command produces the specified next state, and every resulting
   state supports the next command with the same registered event.

Atom-renaming comparison additionally transports $F$, the seed placement, all
reported atom blocks, and the current partition. Event-time positions and
generator labels stay fixed. This is an explicitly requested comparison, not a
license to change the underlying labelled action.

The consumer does not request absolute event times, counts of plateau steps,
the chronology of incomparable events, authorization, checkpoint acceptance,
F3, credit settlement, or POS. Adding any such read changes the specification
and requires a new adequacy argument.
