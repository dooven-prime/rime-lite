# Core Invariants

This file is the reference for the canonical Rubik computation behind the
RIME trilogy and the Computational Canonical Specification (CCS). It records
stable objects, numerical values, and claim-status boundaries for the
foundational Rubik laboratory.

Scope note: this is not the full Papers I--XIII program map. For Papers IV--XIII,
SOF, observable dynamics, and registry evidence, use `docs/PROGRAM_MAP.md`,
`docs/overview.md`, and the paper manuscripts. This file remains public because
the later program depends on these canonical Rubik invariants as calibration
data.

The canonical system is the 228-dimensional Rubik's Cube cubie representation with the standard 18 face-turn generator set. Unless stated otherwise, sectors are defined by the commutative center generated from

```text
Center{A_18, QT_all, HT_all}.
```

This document is not a proof source. Proofs, derivations, controls, and stability checks are in the papers and CCS.

## Governing Picture

The trilogy studies one structural phenomenon at three levels:

```text
spectral projector geometry
        -> transport topology
        -> Lie-generated vs compositional accessibility
```

The unified structural theme is that projector-mediated composition can create accessibility structures that are not captured by the Lie algebra generated from the same representation.

Two principles organize the data:

| Principle | Current status |
|-----------|----------------|
| M2 Principle | Noncommutative simple components are observed, in the verified systems, to carry refinement obstruction, transport mediation, and Lie curvature. This is a computational principle, not a universal theorem in the current trilogy. |
| T7 Principle | Under the stated structural conditions, compositional accessibility can strictly exceed Lie-generated accessibility. The Rubik representation is the certified witness; broader classification is open. |

## 1. Representation Invariant

The cubie representation is a unitary homomorphism

```text
rho(g1 g2) = rho(g1) rho(g2).
```

It preserves four physical blocks:

| Block | Dimension | Meaning |
|-------|-----------|---------|
| `cp` | 64 | corner permutation |
| `ep` | 144 | edge permutation |
| `co` | 8 | corner orientation |
| `eo` | 12 | edge orientation |

Consequences:

- every `rho(g)` is block diagonal with respect to `cp + ep + co + eo`;
- matrix logarithms `A_g = log rho(g)` are block diagonal on the same blocks;
- the Lie algebra generated by the `A_g` cannot create cross-block support.

## 4. Transport Invariant

Transport between sectors is measured by

```text
K_{alpha,beta} = max_g || P_alpha rho(g) P_beta ||.
```

Canonical values:

| Quantity | Value |
|----------|-------|
| primitive sectors | 9 |
| direct transport edges, undirected | 10 |
| Type I noncommutative edges | 9 |
| Type II CP permutation edge | 1 |
| isolated sector | S1 |
| primary hub | S6 |

The transport-active noncommutative block support is

```text
Supp_nc(alpha) = {blocks where P_alpha is supported and the per-axis QT operators fail to commute}.
```

In the canonical Rubik system, 9 of 10 direct edges are Type I edges explained by shared `Supp_nc`. The remaining direct edge is the Type II commutative-permutation channel S8 <-> S9 in the CP block. All direct transport edges are block-preserving.

## 5. T7 Invariant

A T7 morphism is a cross-block compositional channel outside Lie-generated accessibility.

Canonical detection has three layers:

1. Structural disjointness: the endpoint sectors have disjoint block support.
2. Numerical checks: `K = 0`, `kappa_0 = 0`, and `kappa_1 = 0`.
3. Composition: there exists a length-2 path through an intermediate hybrid sector.

For depths `d >= 2`, vanishing of `kappa_d` for cross-block pairs follows structurally from Lie-generated block preservation and disjoint block support, not from a numerical depth sweep.

Canonical values:

| System | T7 morphisms |
|--------|--------------|
| Rubik `N=3` | 5, all cross-block |
| Pocket cube `N=2` | 0 |
| canonical `S_3` negative controls | 0 |

The 5 Rubik T7 pairs are invariant under the canonical detection rule. The reported mediation statistics

```text
S6: 2, S7: 2, S9: 1
```

come from the canonical witness-selection convention and should not be confused with the T7 count itself.

- `experiments/paper3/t7_detection.py`
- `experiments/paper3/transport_9sector.py`
- `tests/test_transport.py`
- CCS Part I, Section 2.5
